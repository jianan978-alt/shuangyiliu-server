# 2025年福建省"双一流"建设监测数据 在线填报系统

多人协同在线版：所有人访问同一个网址，数据实时写入同一个数据库，互相能看到彼此的填报进度。收集人可一键导出全部材料，按"一级指标/二级指标/三级指标"三层文件夹打包成 zip。

## 目录结构

```
server/
├── server.js          后端主程序（Express，提供所有 API）
├── db.js              数据库层（SQLite，自动建表）
├── package.json
├── data/
│   ├── indicators.json   指标数据（结构、负责人分工，来自原始 Excel 整理）
│   └── app.db             SQLite 数据库文件（首次运行自动创建）
├── uploads/            上传的文件实体，按 学科/指标ID/类型 分目录存放
│   └── chem/IND001/evidence/xxx.pdf
└── public/
    └── index.html       前端页面（React，浏览器直接运行，无需构建）
```

## 本地运行

```bash
cd server
npm install
npm start
```

启动后访问 **http://localhost:3000** 即可使用。同一局域网内的其他电脑，用你的电脑局域网 IP（如 `http://192.168.1.5:3000`）也能访问到同一份数据。

## 数据存在哪里

- **文字内容**：存在 `data/app.db`（SQLite 数据库文件）
- **上传的文件**（佐证材料、清单）：存在 `uploads/` 文件夹下，数据库里只记录文件路径
- 备份的时候，把 `data/app.db` 和整个 `uploads/` 文件夹一起复制走即可，不会丢数据

## 关于"多人协同"

- 所有人打开同一个网址，填写内容会实时保存到服务器数据库
- 每个人打开页面后，系统每隔几秒自动刷新一次进度和他人上传的文件，不需要手动刷新页面也能看到别人的最新状态（如果要求更实时，也可以升级成 WebSocket 推送，目前用的是轮询，足够应付这个量级的填报场景）
- 收集人选"我是收集人"入口，能看到全学科所有人的完成百分比

## 导出材料

收集人在"总进度"页面点击 **"导出全部材料"**，服务器会：
1. 按 `一级指标/二级指标/三级指标/` 三层建文件夹
2. 每个三级指标文件夹下放一个 `填报内容.txt`（该指标所有文字字段的内容）
3. 如果该指标有上传佐证材料，放在 `佐证材料/` 子文件夹
4. 如果该指标有上传清单文件，放在 `清单文件/` 子文件夹
5. 全部打包成一个 zip 文件下载，文件名类似 `化学学科_填报材料导出_2026-09-04.zip`

## 部署到云服务器（正式上线时）

本地验证没问题后，要让所有人通过外网访问，需要：

1. **准备一台云服务器**（阿里云/腾讯云/华为云等，2核4G 足够，Ubuntu 系统）
2. 服务器上装好 Node.js（版本 18 以上），把这个 `server/` 文件夹整个上传上去
3. 在服务器上执行 `npm install && npm start`（生产环境建议用 `pm2` 让程序常驻后台：`npm install -g pm2 && pm2 start server.js --name shuangyiliu`）
4. 如果要用域名访问、或者要 HTTPS，前面再加一层 **Nginx** 反向代理到 `localhost:3000`
5. 把服务器的公网 IP 或域名告诉所有填报人即可

代码本身不需要改动，唯一要注意的是：**云服务器的磁盘要留够空间**，因为所有人上传的 Word/PDF/Excel 文件都会实际存在服务器磁盘上（`uploads/` 文件夹会持续增长）。如果材料很多，建议定期把 `uploads/` 备份到其他地方，或者后续升级成对象存储（阿里云 OSS / 腾讯云 COS）。

## 部署到云服务器时可能遇到的坑（实测踩过的坑，提前避开）

**1. `npm install` 超时/ 连不上 registry.npmjs.org**
国内服务器访问国外 npm 源经常很慢或直接超时。先切换成国内镜像：
```bash
npm config set registry https://registry.npmmirror.com
```

**2. `better-sqlite3` 报错 `GLIBC_2.33 not found`**
`better-sqlite3` 的预编译版本要求较新的系统 GLIBC 库，老一点的 Linux 发行版（如 Alibaba Cloud Linux 3 自带 GLIBC 2.32）会装不上。解决办法：换装一个较旧、兼容性更好的版本：
```bash
npm uninstall better-sqlite3
npm install better-sqlite3@9.6.0
```
如果这一步要重新编译，需要先装好编译工具：
```bash
sudo yum groupinstall -y "Development Tools"   # CentOS/Alibaba Cloud Linux
# 或
sudo apt install -y build-essential            # Ubuntu/Debian
```

**3. 服务器本机能访问，外部访问不了**
检查两处：
- `server.js` 里 `app.listen(PORT, ...)` 必须显式绑定 `"0.0.0.0"`（本项目已经这样写了），否则某些环境下只监听本机回环地址，外部连不进来。
- 云服务器的**防火墙/安全组**要开放对应端口（默认 3000）。**注意**：有的云厂商（如阿里云轻量应用服务器）"防火墙模板"和"服务器实例的防火墙"是两个不同的东西，必须在**服务器实例详情页自己的防火墙**里加规则才会真正生效，不要只在模板页面加。

**4. 页面一直卡在"正在加载系统..."**
如果浏览器 Console 报错 `Cannot use import statement outside a module`，这是 Babel 在浏览器里编译 JSX 时默认用了"自动 JSX 运行时"，生成的代码里带了一句 `import` 语句，但页面是普通 `<script>` 标签环境、不支持 `import`。本项目 `public/index.html` 里已经通过注册一个自定义 Babel 预设（`react-classic`，强制使用 `React.createElement` 经典写法）修复了这个问题，如果自己改动过这部分代码，注意别把这个 preset 配置弄丢了。

**5. React / ReactDOM / Babel 用了国外 CDN，加载不稳定**
本项目已经把这三个库下载到本地 `public/vendor/` 文件夹里直接提供，不依赖 `unpkg.com` 等国外 CDN，避免国内网络访问不稳定导致页面加载失败。



代码本身不需要改动，唯一要注意的是：**云服务器的磁盘要留够空间**，因为所有人上传的 Word/PDF/Excel 文件都会实际存在服务器磁盘上（`uploads/` 文件夹会持续增长）。如果材料很多，建议定期把 `uploads/` 备份到其他地方，或者后续升级成对象存储（阿里云 OSS / 腾讯云 COS）。

## 常见问题

**Q: 忘记密码/没有登录验证怎么办？**
目前系统按"选姓名进入"设计，没有账号密码校验（图的是方便，填报人不用记密码）。如果担心有人冒充他人填报，可以后续加一个简单的密码/验证码机制，需要的话告诉我。

**Q: 文件大小有限制吗？**
没有限制文件大小、数量、格式，Word/PDF/Excel 都可以，可以传多个文件到同一个位置。但服务器磁盘和网速是硬性限制，特别大的文件（比如几百MB的视频）上传会比较慢，建议实际使用中留意。

**Q: 两个学科的数据会不会串？**
不会。数据库里每条记录都带着 `discipline`（chem / chem_eng）字段，化学和化工的填报内容、上传文件完全独立存储、独立查询，互不影响。
